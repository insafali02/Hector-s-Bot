At a glanceThis page applies to the Network Intelligence Discord bot and its companion website. Please review it carefully before using the service.

01. Scope

This Privacy Policy explains how the Network Intelligence website and its Discord bot process information when you browse the site, install the bot or run a command. It is written for the referenced bot implementation; the site operator should update it if hosting, integrations or logging practices change.

02. Website data and cookies

This website uses HTML/CSS/JavaScript and serverless API functions to display aggregate bot activity. The provided site does not set visitor-tracking cookies, require accounts, or send browser analytics events. The live dashboard polls only its own public aggregate statistics endpoint. Clicking a Discord button opens an external Discord URL.

As with most hosting services, the hosting provider (for example, Vercel) may process request metadata such as IP address, user agent, approximate location, timestamps and server logs to deliver the website and protect its infrastructure. Review your host’s current policies for exact retention and processing details.

03. Data processed by the bot

When you use the Discord bot, it receives the information needed to perform the requested command. Depending on the command, this may include:

  • Discord user ID, server/guild ID and permissions needed for command handling, owner controls and abuse prevention.
  • Domain names, IP addresses, Minecraft server addresses, ports and CIDR inputs you submit.
  • Public DNS, Minecraft response, geolocation, ASN, registry and network results returned by external sources.
  • Guild names and IDs used in owner-only installed-server reports or join/leave operational logs.

Do not submit credentials, tokens, personal secrets or sensitive account information as command inputs.

04. How data is used

Command information is used to resolve requested lookups, create Discord embeds, enforce owner-managed target blocks, apply cooldowns, deliver paginated results, diagnose errors and maintain bot operations. When optional analytics is enabled, the bot sends a cryptographic HMAC of the user ID, the command name and aggregate guild count to an authenticated analytics API. It does not send message content, command arguments, queried IP addresses or guild identifiers to that API. The website does not provide an account or purchase system.

05. Storage and retention

In the referenced bot version, the global target blocklist is written to the bot host’s .env configuration. The bot also uses in-memory caches for selected API responses and temporary paginated reports. The bot does not require a separate application database for its network commands. However, the optional website analytics feature uses an Upstash Redis database to maintain aggregated counts, a probabilistic unique-user HyperLogLog, daily totals and command-name totals. Those analytics totals start from activation; they are not historical Discord records.

Daily activity keys are configured to expire after 45 days; overall command totals and approximate unique-user counts are retained until the site operator deletes or resets them. Tracking can be disabled by removing the analytics configuration from the bot. Operational console logs may include bot startup status, guild join/leave information, command failure messages and other diagnostic metadata; how long those logs are kept depends on your hosting provider and operator settings. Discord also retains messages/interactions under its own policies. We do not claim an exact hosting-log retention period without confirmed operator configuration.

06. External data providers

To answer a command, the bot may send the requested public IP/domain or related target data to providers such as ipwho.is, RIPEstat, RDAP services, certificate-transparency sources including crt.sh and Cert Spotter, as well as public DNS resolvers. A Minecraft server may also receive a status handshake request.

Those services process requests under their own terms and privacy policies. Not every provider is used for every command, and availability can vary.

07. Sharing and visibility

Slash-command replies and diagnostic embeds may be visible to others in the channel where a command is used. Specific administrative output, including the owner-only installed-server list, is intended to be delivered privately. Never assume arbitrary command inputs or results are confidential in public channels.

Aggregate counts are displayed publicly, but the API does not expose individual hashed identifiers. Data is not intentionally sold through this website. Public lookup data is shared with third-party services only as needed to fulfill the selected command.

08. Security and user choices

Bot operators should keep Discord bot tokens and API credentials private, apply limited role permissions and use approved hosting controls. Server administrators can remove the bot from their server. Bot owners can manage global blocked targets through supported commands.

For privacy questions, correction requests or deletion inquiries involving operator-controlled data, contact the operator. Requests about Discord’s own account or message data may need to be directed to Discord.

09. Policy changes

Changes to provider integrations, logging, retention, hosting or feature scope may require updates to this Policy. The latest revision date will appear at the top of this page.
